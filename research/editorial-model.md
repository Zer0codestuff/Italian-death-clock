# Editorial and simulation model

Implementation-ready specification for a one-page Italian pension-system story aimed at workers aged 20 to 45. The page has a deliberately urgent visual language, but it never turns an uncertain projection into a fake countdown.

## Product contract

Suggested project title: **Il conto della pensione**.

Editorial position: the Italian pension question should be shown as a distribution problem. Someone pays, someone receives, and the terms change when employment, wages, demographics, retirement age, contribution rates, or benefit rules change. The page should make the trade-offs visible without claiming to predict an individual legal entitlement or a national collapse date.

The page must:

- distinguish observed facts, official projections, model estimates, user scenarios, and rhetorical analogies in every chart, card, and paragraph;
- show a personal calculation and a macro pressure calculation using the same visual grammar;
- use euro amounts in constant 2026 euros unless a label says otherwise;
- show checkpoints and scenario bands at 2030, 2040, and 2050, never a single “death year”;
- show the assumptions beside every output, with a one-click method panel;
- avoid collecting names, email addresses, tax codes, or other personal data.

## Truth labels

Use the following visible badges. The badge text is public-facing Italian. The bracketed key is an internal data value used by the content and chart components.

| Public badge | Internal key | Use |
| --- | --- | --- |
| `FATTO` | `FACT` | An observed value or a current rule with a named source and reference date. |
| `PROIEZIONE UFFICIALE` | `OFFICIAL_PROJECTION` | A published projection whose assumptions belong to the source institution. |
| `STIMA DEL MODELLO` | `MODEL_ESTIMATE` | A calculation made by this page from cited inputs. |
| `SCENARIO` | `SCENARIO` | A user-controlled or editorial assumption. It is not a forecast. |
| `ANALOGIA RETORICA` | `RHETORICAL_ANALOGY` | A metaphor or provocation that must not be read as a statistic. |

Every source-backed sentence should carry a source-card ID in the content data, for example `sourceIds: [S1]`. Every scenario number should carry `sourceIds: []` and `label: SCENARIO`.

## Interaction model

1. On load, render the hero and a compact “how to read this” legend. Do not start an autoplay countdown, pulse, siren, or indefinite animation.
2. Scrolling into a scene activates its chart once. The chart has a visible pause button and a “salta al contenuto” link before any animated element.
3. Personal inputs update on `input`, with debounced calculation under 100 ms. Display the last update time as `Aggiornato ora` only for a local calculation. Do not imply that an external data feed changed.
4. Macro inputs update the same output cards and preserve the personal inputs. A reset button restores the documented defaults.
5. A “Confronta con” control lets a user compare the current result with synthetic ages 25, 35, and 45. The comparison holds salary, career start, salary growth, policy settings, and model constants fixed, and varies only the selected age and the resulting retirement year. Label it “confronto controllato”, not a forecast of real people.
6. Shareable state may be encoded in the URL hash or query string. Do not send salary or age to analytics. If a “Scarica il mio scenario” button is implemented, export a local text or JSON snapshot containing inputs, outputs, source-card IDs, and model version.
7. Each chart has a “Apri il metodo” control that exposes formulas, units, source date, and a short limitations paragraph without navigating away from the story.

Fixed model constants must be visible in the method panel:

- `H = 22` years of real payout horizon, `[SCENARIO]`.
- `r_f = 3.0%` annual real funded-pillar return, `[SCENARIO]`.
- `inflation = 0` inside calculations because outputs are in constant 2026 euros, `[MODEL_DEFINITION]`.
- No tax, fee, survivor, disability, means-tested, or minimum-pension calculation, `[MODEL_LIMITATION]`.

The default age of 67 is shown as a model scenario. The current INPS ordinary old-age rule is 67 in 2026, 67 years and one month in 2027, and 67 years and three months in 2028 for the referenced cases. The page must show those values in a dated rule card and must not silently extend them to a user’s future retirement year. See `S3`.

### Equations

Use annual time steps. Let `a` be current age, `r` retirement age, `Y0` contribution years already credited, `F = max(r - a, 0)`, and `Y = Y0 + F` total contribution years at simulated retirement. Let `w0` be current annual gross salary in constant 2026 euros and `g_w` real salary growth.

```
w_j = w0 * (1 + g_w)^(j - Y0)
w_ret = w0 * (1 + g_w)^F
c_public_j = tau * (1 - phi) * w_j
c_funded_j = tau * phi * w_j
```

`tau` is `contribution_rate` and `phi` is `funded_share`. The negative exponent estimates the salary path before the current year from the user’s stated current salary. It is a scenario device, not a reconstruction of payroll records.

Public contributions are carried to retirement at real wage growth. This keeps the public notional balance transparent and avoids pretending to reproduce every legal coefficient:

```
K_public = sum(c_public_j * (1 + g_w)^(Y - 1 - j))
K_funded = sum(c_funded_j * (1 + r_f)^(Y - 1 - j))
```

Convert each balance to an annual real payout with:

```
A(rate, H) = rate / (1 - (1 + rate)^(-H))    when rate != 0
A(0, H) = 1 / H

p_public_annual = public_benefit_factor * K_public * A(0, H)
p_funded_annual = K_funded * A(r_f, H)
p_total_annual = p_public_annual + p_funded_annual
p_total_monthly = p_total_annual / 12
replacement_ratio = p_total_annual / w_ret
```

The output also reports:

```
public_contributions = sum(c_public_j)
funded_contributions = sum(c_funded_j)
total_contributions = public_contributions + funded_contributions
current_annual_contribution = tau * w0
```

Round only at display time. Keep at least six decimal places internally. The monthly result is a 12-month display conversion. It is not a forecast of the Italian 13-payment pension convention.

### Personal outputs

Show these as cards, in this order:

1. `Pensione annua simulata`, euros/year, with the monthly equivalent beneath it.
2. `Tasso di sostituzione lordo`, percentage of the final simulated gross salary.
3. `Contributo annuo oggi`, euros/year and percentage of gross salary.
4. `Versamenti totali simulati`, split between public and funded shares.
5. `Pressione al tuo anno di pensione`, taken from the macro model’s `pressure_index` at `retirement_year`, clearly labeled as a system proxy.
6. `Confronto controllato`, showing the same inputs for synthetic ages 25, 35, and 45.

Never call the result “la tua pensione INPS”. Use “assegno simulato” or “pensione simulata”. Never display a binary “safe/unsafe” verdict.

## Macro simulator

The macro model is a transparent flow proxy. It is not a national accounts model, an INPS actuarial forecast, or a general equilibrium model. Use it to show direction and trade-offs. The locked calibration rows are `employment_base`, `beneficiaries_base`, and `average_gross_wage_real`. The visible panel has seven policy controls: employment growth, migration and demography, productivity, retirement age, contribution rate, benefit and indexation, and funded share. The migration and demography control groups `net_migration` with `beneficiary_growth`; the benefit and indexation control groups `benefit_factor` with `indexation_pass_through`.

The macro base uses the following cited quantities for context:

```
annual_pension_outlay_base = €364.132 billion/year
```

This is the 2024 gross pension income total reported in the INPS annual report, while the beneficiary count is 16.30588 million. Since the employed and beneficiary series do not share an identical statistical definition, compute but label the average as:

```
average_benefit_base = annual_pension_outlay_base / beneficiaries_base
```

The label must say `STIMA DEL MODELLO`, not `pensione media nazionale`. See `S5`.

### Equations

Let `t = 0 ... 25` represent the base year and annual checkpoints through 2050. Let `E_t` be the employed proxy in millions, `R_t` beneficiaries in millions, `M` annual net migration in people, and `d_E`, `d_R` the employment and beneficiary growth rates.

```
E_(t+1) = max(0, E_t * (1 + d_E) + M / 1,000,000)
R_(t+1) = max(0, R_t * (1 + d_R))
w_t = average_gross_wage_real * (1 + productivity_growth_real)^t
```

Apply retirement-age sensitivity only as a clearly disclosed local approximation:

```
age_shift = retirement_age - 67
E_adj_t = E_t * (1 + 0.010 * age_shift)
R_adj_t = R_t * max(0.75, 1 - (age_shift / 22))
```

The `0.010` employment response and `22` year retiree-horizon response are model assumptions. They let the retirement-age control have a visible effect, but they are not sourced elasticities. Include a tooltip: `Questa sensibilità è una scelta del modello, non una stima ufficiale.` `[SCENARIO]`

Define the wage bill and public cash flow:

```
wage_bill_t = E_adj_t * 1,000,000 * w_t
public_contribution_revenue_t =
    contribution_rate * (1 - funded_share) * wage_bill_t

benefit_per_person_t =
    average_benefit_base * benefit_factor *
    (1 + indexation_pass_through * productivity_growth_real)^t
benefit_outlay_t = R_adj_t * 1,000,000 * benefit_per_person_t
```

Outputs are:

```
workers_per_beneficiary_t = E_adj_t / R_adj_t
pressure_index_t = (R_adj_t / E_adj_t) / (beneficiaries_base / employment_base)
required_payg_rate_t = benefit_outlay_t /
    ((1 - funded_share) * wage_bill_t)
balance_proxy_t = public_contribution_revenue_t / benefit_outlay_t
benefit_replacement_proxy_t = benefit_per_person_t / w_t
funded_contribution_flow_t = contribution_rate * funded_share * wage_bill_t
```

Guard against zero denominators and show `n.d.` if a user sets an impossible zero base. The `required_payg_rate` is the rate that would cover the modelled benefit outlay using the modelled wage bill. It is not a tax recommendation. `balance_proxy = 1.0` means modelled public contribution flow equals modelled benefit outlay. It is not the state budget balance, the INPS budget balance, or a debt forecast.

The funded share is deliberately conservative in the macro view. It diverts current flow from the public proxy, but the macro model does not assume that a mature funded pillar immediately replaces public benefits. The personal simulator does model a separate funded account. The UI must show this transition caveat next to the funded control.

### Macro outputs

At each checkpoint, show:

- `Pressione del sistema`: `pressure_index`, dimensionless, baseline equals 1.00.
- `Occupati per beneficiario`: people per person, with the proxy warning.
- `Aliquota PAYG necessaria`: percentage of model wage bill, compared with the selected current rate.
- `Bilancio di flusso proxy`: `balance_proxy`, ratio with a plain-language explanation.
- `Sostituzione media proxy`: modelled benefit divided by modelled gross wage.
- `Quota finanziata`: current contribution flow diverted to the funded pillar.
- `Confronto generazionale`: the same outputs sampled at each synthetic cohort’s simulated retirement year.

Use a three-line chart for pressure, required rate, and replacement. Add a translucent band created by low, central, and high scenarios. The central line must not be styled as a prediction. The legend should read `Scenario basso`, `Scenario centrale`, and `Scenario alto`.

Never output “collasso nel 20XX”, “giorni alla fine”, “zero pensione”, or equivalent. If a user asks for a collapse date through the UI, show: “Il modello non calcola una data di collasso. Mostra pressione, flussi e compromessi.” `[MODEL_LIMITATION]`

## Data visuals and source cards

### Visual rules

- Use an emergency palette with near-black background, off-white text, signal red for warnings, and one high-contrast yellow for scenario controls. Do not use red as the only semantic channel.
- Use large numerals only when the unit, date, and truth label sit within the same card.
- Draw observed values as solid strokes, official projections as dotted strokes, and model scenarios as dashed strokes. Include the style key in text, not only in color.
- Use a cohort dot plot for the generational comparison. Each dot needs a text row with age, retirement year, pressure index, required rate, and replacement proxy.
- Use a waterfall for the personal result: gross salary, public contribution, funded contribution, simulated public payout, simulated funded payout. A separate annotation states that this is a model flow.
- Use a ratio bar for `workers_per_beneficiary`, not a circular gauge that implies a pass/fail threshold.

### Source card schema

Each card has:

```
id, title_it, publisher, publication_date, last_verified,
url, label, claim_it, scope_it, model_use_it, limitations_it
```

Cards are expandable inline. `claim_it` is the only text allowed to present a fact in the public story. `model_use_it` says whether the value is a base input, a comparison fact, or a context-only figure.

## Accessibility and mobile behavior

### Accessibility

- Use semantic `main`, `section`, `nav`, and `footer` landmarks. Give each scene an `h2` and each chart a visible title.
- Every chart has a text table alternative. The table includes checkpoint, unit, value, truth label, and scenario name.
- Use `aria-live="polite"` for the compact result summary. Do not announce every slider tick. Announce after the user stops moving the control.
- Range controls need a paired number input, visible unit, min, max, step, and `aria-valuetext`. Keyboard arrows must reproduce the step shown in the UI.
- Do not encode fact, projection, and scenario only by color or line style. Repeat the label in text and in the table.
- Keep body text at least 16 CSS pixels, maintain WCAG AA contrast, and preserve focus outlines against the black and red surfaces.
- Respect `prefers-reduced-motion`. In reduced motion, reveal charts immediately and replace all transitions with an explicit “Aggiorna grafico” action.
- The alert bar must not flash. The emergency aesthetic comes from typography, spacing, and color blocks, not seizure-inducing animation.

### Mobile

- Use a single column. Move the chart below its explanation and controls; do not pin a chart over the input area.
- Turn every visual into a short card with the key number, unit, label, and one-sentence method note. Show the complete data table below a “Apri tutti i dati” button.
- Use full-width sliders with 44 CSS pixel touch targets and a numeric input for precise edits.
- Keep the source cards accordion-based, with one open at a time. Preserve the source ID in the heading.
- Use a sticky bottom action only for the next meaningful action, such as `Calcola il mio scenario`. It must not cover focus targets or the consent-free source footer.
- Disable horizontal chart panning for the primary message. If a detailed cohort table needs overflow, provide a normal table and a stacked card view.

## Known limitations and implementation risks

- The personal model is an educational cash-flow and annuity model. It is not the Italian contributory calculation and must never imitate an official calculator screen.
- The macro base combines broad employment, beneficiary, and pension-income series. This is intentional for legibility, but the definition mismatch must remain in every macro view.
- Retirement-age sensitivity is a chosen elasticity. It is useful for a local “what if”, not for an official projection.
- The funded pillar is represented differently in the personal and macro views. The macro view shows the transition effect and the personal view shows an account-style payout. Keep the explanation adjacent to both charts.
- Current rules and source figures can change. Store source dates, show the last verification date, and require a content review before publishing updated values.
- Net versus gross replacement, 12-month display conversion, and constant 2026 euros are easy to confuse. Repeat the unit beside every output and in the downloadable snapshot.
